# Trace Viewer 实用化重设计（2026-08-07）

依据：全量代码审计（9 页面/42 API/桥 9 action）+ AC Express 通宵评测的实际工作流。
北极星：**发现 → 假设 → 实验 → 比较 → 改进** 的完整回路都能在平台里走完，
不写代码就能复现我们在命令行做出的结论（换 prompt 跑 A/B、看分层 metrics、
从失败 cell 一键钻进 trace、在消息行上直接看到问题）。

## 诊断结论（审计要点）

1. **导航即地图的缺失**：9 条平铺路由，每页自建不同的链接行，无处看到全貌。
2. **读写混杂**：`/ace` 把 30 字段发起表单焊在 run 详情上；4 张语义重叠的表。
3. **标注 over-design**：单页 31+ 控件；evidence 消息 ID 要手打；transcript 可见不可点；
   快捷键要先点 focus；队列侧栏塞 9 个过滤器。
4. **Lab ≠ Playground**：名字承诺交互实验，实际是批处理表单；真正的 fork/回归
   能力藏在 TracePage 的 9 个 tab 里；无法对模拟世界多轮对话。
5. **两套 failure 数据源**（metadata.aceFailures vs evaluation.failures）内联 chip
   与 Evaluation 表可能对不上；detector tier/family 不到消息行。
6. **ACE 域硬编码**：8 工具白名单、issue/语言词表、订单实体、退款契约、
   escalation 指标散布在 6+ 处，换 coding 语料评估层全碎。
7. **重复面**：HomePage 的 AceDashboard ≈ 整个 /ace/analysis。

## 保留资产（不推倒）

filter DSL + URL 即状态；连接器注册表（8 格式）；认证模型；桥客户端
（READY/launchToken/幂等）；消息渲染层与虚拟化；SSE journal；
FailureChips 锚定 + EvaluationTab 双向跳转。

## 目标信息架构

持久左侧全局导航（唯一地图），五个工作面，每面一件事：

```
Traces      浏览与发现（原 Home 瘦身：表 + 侧栏筛选；聚合仪表卡收缩为顶栏 KPI 条）
Runs        跑批与结果（run 详情只读为主；「New run」是抽屉；一张 episodes 表）
Experiments 多臂对比（实验历史持久化；变体矩阵；结果表内联 + Δ/CI；失败格钻取）
Playground  交互实验台（对模拟世界改 prompt/开关 playbook/workflow、fork、存回归）
Reviews     标注（快路径一屏一问；细节渐进披露）
```

TracePage tab 9 → 5：`conversation | evaluation(含 state/world-diff) |
rerun(合并 replay+playground，明确标注 exact-fork vs LLM-only) | review | raw(含 metadata)`。
Analysis 页并入 Runs（选中多 run 时出现对比视图），消除与 Home 仪表的重复。

## P0（今天可用，按此顺序实施）

### P0-1 全局导航 shell
`src/App.tsx` 加持久 `<NavRail/>`（五面 + 当前 run/实验上下文徽标），
删除各页自建链接行。所有页面从此可互达。

### P0-2 Runs 页读写分离 + 单表化
- `AceRunLauncher` 移入右侧 Drawer（「New run」按钮触发），run 详情默认只读。
- 4 张表合 1：episodes 主表（Task/Seed/Status/Outcome/Messages/Diagnosis/→trace），
  顶部 chips：`All | In progress | Failures only | Invalid`；
  10 数字格 → 6（Scheduled/Pass/Fail/Invalid/Pass rate/Cost）。
- 告警条合并为一个可展开的「Issues (n)」。

### P0-3 Review 快路径（用户点名痛点）
- 首屏只有：Verdict 三大按钮（P/F/？）+ 一行 note + Submit（⌘Enter 全局可用，
  textarea 内也生效）+ Next/Prev。
- 「Details」手风琴收纳：rubric 维度、automatic failures、turn annotations、
  ground truth（默认折叠）。
- **transcript 消息可点选**：点击即加入/移除 evidence（替换手打 ID input）；
  rootCauseTags 用 datalist 从历史 tag 补全。
- 队列侧栏过滤器收进一个「Filters」popover，列表回到全高。
- 删导航一致性状态机，队列游标简单化（本地数组 + 越界重取）。

### P0-4 失败数据源统一 + 消息行可发现性
- 载入时合并 aceFailures/evaluation.failures 为单源（以 evaluation 为准，
  metadata 仅补位），chip 显示 `code · tier/family`，颜色按 gating。
- 所有 tab 加计数徽标；`evaluation` 吸收 `state`（world diff/ledger 是
  evaluation 证据的一部分）。
- Conversation 工具条加按 role/severity/failure 过滤（复用现有搜索管线）；
  Timeline/Compact 模式下禁用的控件加禁用原因 tooltip。

### P0-5 Playground 第一步（不改桥）
- `/ace/lab` 更名 Playground，页面 = 左配置（prompt 可编辑 textarea + preset、
  playbook/workflow 开关、model/temp）+ 右会话区。
- 会话区 MVP：选 scenario → 「Run one episode」→ 流式（message_complete 粒度）
  渲染对话 + 工具调用 + 判分结果；「Fork from turn」「Save as regression」
  按钮直接调用既有 bridge action（从 ReplayTab 提升为一等公民）。
- 多轮人工输入（真 interactive）标注为 P1（需桥新 action，见下）。

## P1（本周）

- **桥新增 `interactive` action**：起一个挂起的 episode 会话，user turn 由
  平台注入（ctl 文件或 stdin 协议），支持逐轮执行工具与判分——真 playground。
- **Experiments 持久化 + 矩阵**：实验记录写 `.trace-viewer/experiments.jsonl`；
  变体数从 2 放开到 N；结果表内联（pass/esc/guardrail/Δ + bootstrap CI，
  复用 ace analyze）；每个失败 cell 一键开 trace 列表。
- **Prompt 库**：preset 下拉从桥 capabilities 拉取（列 configs/prompts/*.md +
  digest），支持命名保存新版本；A/B 变体直接引用库版本。
- **用户质量板块**：LLM-user run 的 user_quality 指标进 run 详情
  （validity/语言/意图/稳定性），不合格标红——评测可信度前置。

## P2（跨数据集 adapter）

把 §6 审计列出的硬编码收敛为 **DomainAdapter 接口**（TS + 桥两侧）：
`{ toolManifest, outcomeVocab, entityKey(如 order_id→file/PR), personaFields,
  detectorRegistry, groundTruthSchema, regressionSchema }`。
ACE = 第一个 adapter；coding agent = 验证用第二个（diff/test 视图属于该
adapter 的 trace 增强件）。escalation 类指标声明在 adapter 里，分母为 0 的
tile 不渲染。

## 明确的假设修订（原设计 → 新设计）

| 原假设 | 修订 |
|---|---|
| 一个页面可以同时服务发起/监控/分析 | 每面一职，写操作进抽屉 |
| 标注越全越好（250 rubric/1000 failure 上限） | 快路径优先：verdict+note 即可提交；细节渐进 |
| detector 结果属于独立 tab | 问题必须出现在它发生的消息行上 |
| prompt 三档预设够用 | prompt 是被实验的一等对象：库 + 版本 + digest |
| ACE schema 即 trace schema | Domain adapter；ACE 只是第一个实现 |
| playground=LLM 续写 | playground=对真实模拟世界的交互实验台 |
